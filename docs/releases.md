# Releases and verification

The release definition is `.goreleaser.yaml`, using GoReleaser 2.18.3 and Syft 1.55.0. The tag workflow is `.github/workflows/release.yml`. It builds Linux/macOS by amd64/arm64 with CGO disabled, `-trimpath`, and `-X main.version=<tag without v>`. No signing key is stored in the repository.

## Local dry-run

Install the pinned GoReleaser and Syft versions from their official releases and verify their release checksums before running them. A Go SDK and Git are required. With both tools on PATH, from the repository root:

```sh
goreleaser check
goreleaser release --snapshot --clean
python3 scripts/release-metadata.py --check-snapshot dist
```

This creates an unsigned, unpublished snapshot in `dist/`. `--clean` clears that generated directory. Snapshots do not require a GitHub token, Cosign, OIDC or a release tag. With no local tags, GoReleaser chooses a `0.0.0-SNAPSHOT-<commit>` label; it is not a release version. `scripts/release-assets.sh` is a compatibility wrapper for this same snapshot command.

Expected payloads:

| Asset | Count | Use |
| --- | ---: | --- |
| `taintwatch-{linux,darwin}-{amd64,arm64}` | 4 | Raw binaries, exact launcher download names |
| `taintwatch_<version>_<os>_<arch>.tar.gz` | 4 | Binary plus README, LICENSE and CHANGELOG |
| `<archive>.sbom.json` | 4 | Syft SPDX JSON inventories |
| `checksums.txt` | 1 | SHA-256 for all twelve payloads, including SBOMs |

Raw binaries remain in GoReleaser's platform build directories in `dist/`; archives and SBOMs are at its root. GoReleaser's metadata records the release names. Platform-specific binaries inside archives have the same name as the raw asset. Snapshots have no `checksums.txt.sigstore.json`: the real tag workflow produces that signature bundle before uploading anything.

## Preparing a tag

1. Review the security/evaluation status and complete the private reporting contacts. The currently documented benign TW009 mismatch still fails the strict eval gate; this pipeline does not bypass it.
2. Update `.claude-plugin/plugin.json` and the launcher's `version=` to the same version. Move reviewed changes into a nonempty `## [VERSION] - YYYY-MM-DD` section in CHANGELOG.md. The workflow refuses missing/empty notes or mismatched versions rather than silently publishing Unreleased or autogenerated commit messages.
3. Run the snapshot and tests. `python3 scripts/release-metadata.py v0.1.0` previews notes for that version once its changelog section exists; on today's Unreleased-only changelog this command intentionally fails.
4. Review and push a matching `v*` tag when ready to publish. This documentation task did not create or push a tag or release.

The read-only verify job runs metadata checks, helper tests, build/race/lint, strict eval and shellcheck. Only the publishing job has `contents: write` and `id-token: write`. All actions are pinned to resolved commit SHAs, tools to release versions; the Syft Linux archive and Cosign binary also have pinned digests. Checkout does not persist credentials. Review SHA/tool/digest updates together; Dependabot covers action references.

The publishing job builds with GoReleaser using `--skip=publish`, then uses Cosign 3.1.4 to keylessly sign `checksums.txt` through GitHub's OIDC identity. It immediately verifies the exact workflow/tag identity. It rechecks every checksum-covered payload before creating the GitHub release with the extracted changelog notes. A signing, identity-verification, missing-asset or checksum error stops publication; there is no silent unsigned fallback. A failed partial GitHub upload needs manual review/repair before retrying, rather than overwriting existing assets automatically.

## Verify a published release

These are instructions for a future published release, not a claim that v0.1.0 artifacts currently exist. Install Cosign 3.x and obtain `checksums.txt`, `checksums.txt.sigstore.json`, and the desired asset from the same tag. In a fresh directory, choose the intended tag explicitly:

```sh
tag=v0.1.0
base="https://github.com/ratuhin1122/taintwatch/releases/download/$tag"
for asset in checksums.txt checksums.txt.sigstore.json taintwatch-linux-amd64; do
  curl --fail --silent --show-error --location --proto '=https' --proto-redir '=https' "$base/$asset" -o "$asset"
done
cosign verify-blob \
  --certificate-identity "https://github.com/ratuhin1122/taintwatch/.github/workflows/release.yml@refs/tags/$tag" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --bundle checksums.txt.sigstore.json checksums.txt
sha256sum --check --ignore-missing checksums.txt
chmod 700 taintwatch-linux-amd64
./taintwatch-linux-amd64 version
```

Stop if either verification fails. Do not replace the exact expected identity with an unrestricted regular expression. GNU `sha256sum --ignore-missing` verifies files present in the directory, not every asset listed; require the intended asset to be present. On macOS, install GNU coreutils or verify the specific filename with `shasum -a 256` and compare its complete digest to the signed manifest before execution. ARM/macOS users must choose their matching asset, not run the Linux amd64 example.

The launcher fetches `https://github.com/ratuhin1122/taintwatch/releases/download/v<plugin-version>/taintwatch-<os>-<arch>` and `checksums.txt`. It verifies SHA-256 and rehashes cached bytes, but **does not verify the Cosign identity or bundle**. Same-release checksums detect corruption; they do not independently authenticate a compromised release. For identity-verified installation, follow the manual verification first and place the verified binary on PATH or in the bundled platform path. Hooks disable network bootstrap; only an explicit non-hook first invocation can attempt it, and failed attempts are not silently retried.

## Advisory security scans

CI installs govulncheck v1.9.0 and gosec v2.29.0 in a separate read-only Ubuntu job. Both scans run against `./...` with a four-minute process limit, report their exit status/output in the job summary, and retain full output in the job log. Gosec excludes local tooling caches and generated build/dist directories. Exit 124 explicitly denotes timeout; it is not a clean scan. Findings, installation failures and missing scanners are advisory initially; a failure is never described as a clean scan. Scanner steps use `continue-on-error`, while the regular tests and eval gate remain blocking. Scanner modules are CI tools and are not product dependencies.

## M4.4 local verification (2026-10-22)

`goreleaser check` and the exact `goreleaser release --snapshot --clean` command passed using GoReleaser 2.18.3, Syft 1.55.0 and Go 1.27.0 on the Windows build host. The snapshot label was `0.0.0-SNAPSHOT-70b53ba` because this local repository has no tags. `python3 scripts/release-metadata.py --check-snapshot dist` rehashed all twelve unique payloads successfully. All four SBOMs parse as SPDX-2.3 and each contains five package records. Both Linux and Darwin executable formats were built; only Linux execution was checked in WSL.

The Linux launcher suite passed its successful fake release download, wrong-checksum rejection, cached-byte tampering and no-retry/no-hook-network cases. Shellcheck passed for the launcher, snapshot wrapper and advisory scanner runner. Release helper tests cover note extraction, missing/empty notes, version mismatch, malformed tags/checksums, complete asset lists, and the required signature-file boundary. These local checks do not execute GitHub OIDC or publish a release.

GoReleaser logs raw-binary artifact-name warnings because upload names intentionally match the built filenames. Its checksum output contains exactly one record per release filename; the separate publisher rechecks and uploads each payload once. The workflow never uploads GoReleaser metadata/config files.

The local govulncheck v1.1.4 run exited 0: zero reachable vulnerabilities, with one imported-package and thirteen required-module advisories reported outside the reachable-call result. This is a point-in-time source scan, not a claim that all dependencies are vulnerability-free.

The bounded local gosec v2.29.0 run exited 1 and reported 15 findings across 73 files on the Windows build host; its advisory summary preserved that exit status and report. Unix-only files and analyzer results can differ in the Ubuntu CI scan. The initial unbounded local scans traversed the downloaded module cache; the final wrapper excludes those generated/cache directories. Findings were not silently suppressed or fixed as part of release packaging.
